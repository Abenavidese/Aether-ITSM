PLAN DE IMPLEMENTACION - AETHER ITSM
Ultima actualizacion: ver historial de git de este archivo.

Como usar este documento
-------------------------
Las fases estan en orden de cascada: cada una depende de que la anterior
exista, no solo de que "tenga sentido" hacerla antes. No saltar una fase
sin haber marcado sus items como hechos, o la siguiente se construye sobre
algo que no esta ahi todavia.

Cada item tiene: que es, por que va en ese orden (de que depende), y que
archivos toca aproximadamente. Se implementa de a uno, y se marca [DONE]
al terminar.

BUGFIX POST-FASE 6: ALUCINACION DEL CONCIERGE EN PREGUNTAS DE CODIGO/ARCHIVOS
-----------------------------------------------------------
Encontrado con Ollama real (no hipotetico): al preguntar "revisa el codigo
del repo y mira si hay errores" el modelo respondio con total confianza
"no encontre errores"; al preguntar "listame los archivos en controllers"
directamente invento nombres de archivo (rateLimiter.js, verifyTokenAdmin.js...)
que no existen en el repo real.

Causa raiz doble:
1. No existia NINGUNA capacidad para enumerar un directorio - search_code
   (Fase 6) busca CONTENIDO que matchee un texto, no puede listar una
   carpeta. Un mensaje tipo "listame los archivos" ni siquiera disparaba
   _CODE_QUESTION_PATTERN (no menciona "codigo"/"repo"), asi que el LLM
   respondio sin ningun dato real.
2. El prompt del Concierge no prohibia inventar cuando no hay contexto real.

Fix (src/integrations/github.py + src/agent/concierge.py):
- get_repo_tree(repo, token): un solo call a la API recursiva de git trees
  de GitHub (no la API de Contents, que exige ya saber el path exacto) -
  devuelve el arbol completo del repo, asi el agente puede encontrar "la
  carpeta controllers" sin conocer de antemano su path completo.
- _DIRECTORY_QUESTION_PATTERN + _extract_keywords: heuristica separada de
  la de busqueda de codigo, matchea sobre los ultimos 3 mensajes (no solo
  el actual) para capturar seguimientos cortos tipo "y en middleware?" que
  no tienen palabra disparadora propia.
- Instruccion CRITICAL explicita en el prompt: solo afirmar lo que aparece
  literalmente en el contexto o en un resultado real de tool: nada de
  "revise el codigo" o inventar archivos sin datos reales detras.
- Verificado contra el repo real (Abenavidese/core-ecommerce-api, no un
  mock): _directory_listing_context('...controllers...') y
  ('...middleware?') devolvieron exactamente los archivos reales
  (authController.js/cartController.js/orderController.js/productController.js
  y auth.js/errorHandler.js/wrap.js respectivamente). Suite pytest: 7/7.


BUGFIX: CONCIERGE NO ENCONTRABA CARPETAS DEL REPO ("que hay en /src/agents")
-----------------------------------------------------------
Encontrado en el chat real: "revisa el repo y dime que hay en /src/agents"
-> "No encontre informacion". Causa: el mensaje no tenia palabra gatillo de
directorio (lista/carpeta/archivos), asi que nunca se consulto el arbol; y
aun si se consultaba, "repo" matcheaba por substring "repositories/" y se
habria listado la carpeta equivocada. Fix en concierge.py: rutas explicitas
(_PATH_PATTERN) se resuelven por sufijo ("src/x" -> "backend/src/x"); ruta
inexistente -> negativa deterministica + contenido real del padre + nombres
parecidos; el substring solo cuenta si cubre >=80% del nombre; si una
pregunta de repo no da resultados en search_code, se pasa la estructura
real. Prompt: responder en el idioma del usuario, y una respuesta negativa
informativa es resolved=true (no abre ticket). tests/test_concierge_directory.py
(6 casos) + verificado con Ollama real contra core-ecommerce-api.


BUGFIX: EL CHAT SE QUEDABA CONGELADO (LLM GENERANDO SIN FIN)
-----------------------------------------------------------
Diagnosticado con el log de Ollama (no hipotetico): una sola llamada llevaba
27k+ tokens generados ("pero si /src/agents no existe pero si ..."), con
context shift sin fin. Cadena: (1) ChatOllama sin num_predict -> Ollama
genera para siempre si el modelo entra en bucle; (2) invoke_structured
reenviaba el parsing_error completo, que incluye toda la salida basura
(prompt de 41.878 tokens); (3) Ollama trunca el prompt POR EL PRINCIPIO
-> se perdia el system prompt y el modelo seguia el bucle. Fix:
LLM_MAX_OUTPUT_TOKENS=1024, LLM_TIMEOUT_SECONDS=120 (Ollama y OpenAI/Nebius),
OLLAMA_NUM_CTX=8192 (cabe entero en VRAM, 5.9 GB); el reintento parte de los
mensajes originales + error resumido a 300 chars. Verificado: la misma
conversacion que colgaba ahora responde en 17-30s (3/3 corridas).
Tambien: validador _ungrounded_repo_names en concierge.py (archivos/rutas
nombrados en la respuesta deben existir en el arbol real o en lo que escribio
el usuario; si no, un reintento y luego respuesta deterministica) y rutas
estilo Windows ("\src\agent") reconocidas.


CONCIERGE: LECTURA REAL DE ARCHIVOS DEL REPO
-----------------------------------------------------------
Problema: el agente solo veia NOMBRES (arbol), nunca el contenido, asi que
no podia diagnosticar nada; y el listado de "lo que si existe" dependia de
que el 8B lo copiara (a menudo respondia solo "no existe").
- get_file_content(repo, token, path) en src/integrations/github.py
  (Contents API, raw). El path sale del arbol real server-side, nunca del LLM.
- concierge.py: RepoView (context, listed_dirs, files, fallback). Se leen los
  archivos nombrados en el mensaje, o los de una carpeta cuando hay intencion
  de revision (_REVIEW_PATTERN: revisa/errores/explica/que hace...). Nunca los
  de carpetas mostradas solo como alternativa a una ruta inexistente.
  Presupuesto 6000 chars / max 4 archivos, con numeros de linea y cabecera
  explicita "COMPLETE FILE, N lines" / "PARTIAL" (con un marcador condicional
  "TRUNCATED" el 8B afirmaba que un archivo completo estaba cortado).
- _verified_listing_footer: si la respuesta omite entradas del listado real,
  el codigo lo agrega al final. El listado ya no depende del LLM.
- ConciergeResult.details (list[str]): bajo JSON forzado el modelo cerraba
  response_text justo en "aqui te explico cada uno:" y la lista se perdia
  (done_reason=stop, 54 tokens). Ahora los items van en details.
- Prompt: en revisiones siempre veredicto (problemas con archivo:linea, o
  "sin errores evidentes" + resumen) y resolved=true.
Verificado con Ollama real contra core-ecommerce-api: "\src\agent" -> no
existe + listado real garantizado; middleware -> explicacion correcta de
auth.js/errorHandler.js/wrap.js; authController.js y server.js -> revision
con veredicto. 30/30 tests.
