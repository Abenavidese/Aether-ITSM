# UX & Interaction Flows (Aether ITSM)

## 1. End User Journey (L1 Auto-Resolution)

**Scenario:** User needs a password reset or VPN access.
1. **Trigger:** End user opens a ticket via the ITSM portal or sends a message in Slack/Teams (integrated via ITSM).
2. **Immediate Feedback:**
   - The ticket receives an automated comment within 5 seconds: 
     > *"🤖 Aether AI is reviewing your request. Please wait a moment."*
   - Status changes to: `In Progress (AI)`.
3. **Resolution:**
   - Within 30 seconds, Aether executes the workflow.
   - The ticket receives a resolution comment:
     > *"🤖 **Action Completed:** Your VPN session has been reset. Please try connecting again. If the issue persists, reply to this ticket to escalate to a human agent."*
   - Status changes to: `Resolved`.

## 2. IT Agent Journey (L3 Assist-and-Gate)

**Scenario:** User requests access to a production database (High Risk).
1. **Trigger:** End user requests access. Aether classifies this as Risk Level 3.
2. **Agent Proposal (Pausable State):**
   - Aether does **not** execute the action. It drafts a plan and adds an internal note (Work Note) visible only to IT staff:
     > *"🤖 **Aether Proposal (Approval Required):**
     > **Intent:** Grant ReadOnly access to Prod_DB for user `j.doe`.
     > **Risk Level:** 3
     > **Proposed Action:** Execute MCP Tool `add_iam_policy` with payload `{"user": "j.doe", "policy": "arn:aws:iam::prod:policy/ReadOnly"}`.
     > 
     > [Approve Plan] | [Reject & Modify]"*
3. **Human Action:**
   - The L2/L3 IT Agent reviews the Work Note in Jira/ServiceNow.
   - The IT Agent clicks the "Approve" button (or replies with the exact phrase "/approve").
4. **Execution & Closure:**
   - Aether resumes execution, runs the approved tool, and resolves the ticket, leaving an audit trail:
     > *"🤖 **Action Executed:** IAM Policy applied. (Approved by: admin_user_id)"*

## 3. UI/Formatting Standards
- All comments generated by the AI must start with a robot emoji `🤖` to clearly distinguish them from human actions.
- Any actions involving execution (Level 2 or 3) must include an **Audit Trace** section in the final comment.
