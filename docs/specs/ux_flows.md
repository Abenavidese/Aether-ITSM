# UX & Interaction Flows (Aether ITSM)

> **Status** (reviewed against the code on 2026-09-26, roadmap 1.3): the original draft
> described the whole experience inside Jira/ServiceNow comments. That integration doesn't
> exist (see `itsm_integration.md`); the flows below are what runs today, with the ITSM
> versions kept as **Planned**.

## 1. Employee journey — Implemented (Aether web portal)

1. The employee opens the portal chat (`/chat`) and describes the problem, optionally
   attaching a screenshot (png/jpeg/webp, ≤ 5 MB).
2. The **Concierge** answers in the same turn when it can: company policy (RAG), technical
   docs, the tenant's real repository (files, code search), service health and, for outage
   reports, a read-only look at platform logs. A screenshot is read by the vision model, so
   its error text and file:line count as part of the report.
3. If it needs an action (access, software, a human decision) it opens a ticket and the full
   agent swarm runs it through the queue; the chat polls and posts the outcome
   ("resolved" / "escalated" with the GitHub issue link).
   **Partial:** polling stops after ~1 minute (roadmap 3.4).

**Planned:** the same journey from Slack/Teams (roadmap 3.6) and status comments inside the
ITSM ticket ("🤖 Aether AI is reviewing your request…").

## 2. IT admin journey — L3 assist-and-gate — Implemented (Aether dashboard)

1. A ticket assessed at risk 3 (e.g. production access) is not executed. `draft_plan` writes
   a human-readable plan plus the exact validated tool call.
2. The admin sees it in the dashboard's human gate panel — plan and exact action — and
   approves or rejects.
3. Approved: that frozen call runs (no LLM involved) and the ticket resolves. Rejected: the
   ticket is escalated (GitHub issue if configured).

**Planned:** the proposal as an internal Work Note in Jira/ServiceNow with an approve
transition there.

## 3. Formatting standards
- **Implemented:** escalation issues are generated by code with ticket text redacted and
  fenced (no live mentions/links/images).
- **Planned:** a 🤖 prefix and an "Audit trace" section on ITSM comments (no ITSM comments exist yet).
